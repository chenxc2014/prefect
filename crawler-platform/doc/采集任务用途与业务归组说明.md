# 采集任务用途与业务归组

2026 年 11 月 18 日，Linux 169 开发环境已启用任务用途分类。入口为 `https://192.168.1.169:8443/collector/`。

## 如何识别任务

平台按使用目的区分三类：业务采集、模拟演示、测试验收。是否真实打开浏览器、是否产生文件、是否执行成功，都不能代替用途分类。旧任务缺少分类时显示“待分类”，不会自动纳入业务采集。

平台概览顶部保留“三种采集方式，一个管理入口”的介绍横幅，并压缩高度。横幅下依次为运行与调度、已发布任务情况、设计与接入；架构说明默认折叠。

运行与调度区域以独立大卡片显示 Prefect 服务状态，并将业务定时采集是否配置单独说明。另外三张卡片显示正在执行、等待或暂停的运行数量，以及业务采集任务数量。状态读取失败时显示未确认或“—”，不误报正常或零运行。

已发布任务区域当前包含业务采集版本 2 个、模拟演示版本 1 个、测试验收版本 5 个，共 8 个活动版本。默认展示千金商品流向这一项业务的两种引擎实现，可在概览直接切换用途，查看各版本当前运行、定时调度和最近结果；点击“查看与运行”进入对应版本操作。

任务列表默认展示业务采集。千金商品流向归为同一任务，包含 Maxun 和 EasySpider 两种引擎实现。用途筛选的数量按活动版本计算，分组标题同时显示引擎数和活动版本数。

## 如何发布

Maxun 和 EasySpider 发布入口均须选择任务用途，并填写所属任务名称。同一业务的不同引擎使用同一所属任务名称，平台按“用途 + 所属任务名称”归组；版本自己的发布名称、执行节点仍单独保留。

新版本的用途字段为 `purpose`，枚举为 `business`、`demo`、`acceptance`；所属任务名称字段为 `task_name`。调用发布 API 时同样必填。缺少用途会返回 HTTP 400，Maxun 不会因此创建发布副本。

## 如何判断是否在运行

发布数量表示可选择的活动版本数量。任务卡另外显示当前执行数量、等待或暂停数量、定时调度状态和最近一次运行结果，并提供 Prefect 运行链接。

页面每 30 秒读取 Prefect 状态。定时调度按其实际参数关联到固定模板版本；同一执行节点上的其他任务不会被误报为已配置调度。状态读取失败时显示待核对，不将失败误报为没有运行。

概览的运行计数覆盖当前活动版本；更早版本的运行记录仍可在 Prefect 查看。浏览器关闭时页面停止刷新状态，不影响服务器执行。

## 现有版本迁移与验证

现有 8 条的分类清单在 `deploy/catalog-classifications.json`，其中千金 2 条为业务采集，模拟销售 1 条为模拟演示，其余 5 条为测试验收。Linux 与 Windows 日期验收归为同一项测试的两个节点实现。

现有版本通过目录 `.metadata/<版本号>.json` 补充分类。原始模板内容、版本摘要和 `.heads` 活动指针均未修改，历史运行继续对应原版本。

预览分类迁移：

```powershell
python -m tools.classify_catalog --catalog <目录> --mapping deploy/catalog-classifications.json
```

确认清单后添加 `--apply` 写入分类。迁移脚本会检查版本文件和活动指针摘要保持不变。

发布及界面验证记录见 `doc/任务用途分类部署记录.json`、`doc/任务用途分类界面验收.json`。浏览器验收脚本为 `tools/task-catalog-browser-check.mjs`，通过本机 SSH 验收隧道检查真实页面，不发布新版本、不提交采集运行、不连接 Windows 167。

本次通过 37 项单元与接口测试，覆盖既有版本补分类后内容和活动指针不变、按用途与任务归组、发布必填校验、版本之间的运行记录隔离、调度参数覆盖及暂停状态，并回归原有模板、Maxun 和统一登录行为。真实页面检查覆盖桌面、平板、手机布局和用途筛选。

概览布局调整的部署和浏览器验收另见 `doc/概览布局部署记录.json`、`doc/概览布局界面验收.json`。覆盖 1920、1440、1280、1024、768、390 像素宽度，确认介绍横幅保留、Prefect 卡片位于首屏、已发布任务按用途切换，以及服务异常和运行状态读取失败时不会误报正常或零运行。异常场景仅在验收浏览器内模拟，不修改服务器状态。
